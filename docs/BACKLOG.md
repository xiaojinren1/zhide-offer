## B1 · 清理测试噪声与孤儿表

**问题**
- 全量 `unittest discover` 里有 `tests/test_accounts.py` 2 项长期失败，另有
  `test_model_errors` / `test_tool_loop` 在 discover 下报错而单独跑通过——回归信号被噪声盖住，
  以后分不清"我弄坏的"和"本来就坏的"。
- 账户库里存在 `registration_codes` / `registration_send_limits` 两张表，代码零引用（早期邮箱注册实验残留）。

**验收**
- 全量 discover 只剩真实失败（理想为零）；已知既有失败要么修掉，要么在 HANDOFF 里写清原因与判定方式。
- 孤儿表从 schema 与现有库中移除，启动不再创建。

**结果（2026-11-12）**
- 把 6 个"导入即执行"的检查脚本从 `tests/test_*.py` 改名为 `tests/run_*_qa.py`：
  `tool_loop`、`llm_providers`、`deadlines`、`context_slimming`、`example_lib`、`suspicion`。
  它们会在 import 时改写 `core.llm` 的全局函数、动真实 `data/`，是发现不了串扰的根源。
  改完后 `unittest discover -p "test_*.py"` **308 项全绿**（之前 23~27 条 FAIL/ERROR）。
- `run_tool_loop_qa.py` 从"匿名客户端 + 真实 data 目录"改成临时数据库 + 依赖覆盖的已登录账户，
  脚本自身 5 条长期失败归零，也不再删除 `data/profiles` 下的真实文件。
- `tests/test_accounts.py`：修掉一段误粘到模型用量用例尾部的 trial 测试片段（引用未定义的
  `guest`）；统计接口断言改为按关键字段比较，允许后加的 trend 字段但不允许带出个人数据。
- 删除弃用的 `registration_codes` / `registration_send_limits`（代码零引用、无数据），
  在 `schema.ensure` 里幂等 drop。

**约定（后续照做）**：`tests/test_*.py` 只放 unittest 用例；脚本式检查一律 `tests/run_*_qa.py`，
不得在 import 时执行检查、改全局或读写真实 `data/`。

## B2 · 投递看板

**问题**：`applications` 表 0 行、无接口无页面，用户"投过哪些、下一步干嘛"无处记录。

**做法**：状态机 `saved → tailored → applied → interview → offer / rejected / archived`；
`POST /api/jobs/{doc_id}/application` 推进状态、`GET /api/jobs/applications` 列表；
收件箱详情加状态条、列表加"投递中"筛选；只记 `next_action_at`，不做推送。

**验收**：一个岗位 saved→interview 全程留痕且刷新仍在；同一岗位只有一条记录（已有唯一索引
`idx_applications_doc`）；他人看不到别人的投递记录。

**结果（2026-11-12）**
- 新增 `engine/documents/applications.py` + `application_events` 留痕表：
  `saved → tailored → applied → interview → offer`，任意非终态可 `rejected / archived`，
  归档后能重新 `saved`；非法跳转返回 422 并列出可选状态。
- 接口：`GET /api/jobs/applications`（阶段筛选、每阶段计数、默认排除归档）、
  `GET /api/jobs/applications/{doc_id}`（含留痕）、`POST`（加入或推进，可带备注与
  `YYYY-MM-DD` 的下一次动作）、`DELETE`（移出看板，连带删留痕）。
- 前端岗位收件箱：详情里新增「投递状态」条（当前阶段、备注、下一次动作、可选推进按钮、
  状态留痕折叠列表、移出看板）；列表卡片加阶段徽标；顶部加投递状态筛选与"进行中 N 个岗位"。
- 验收：`tests/test_applications.py` 9 项覆盖 saved→interview 留痕、唯一记录、非法跳转、
  未加入直接推进、账号隔离、归档默认隐藏并可重启、删除连带留痕、删岗位级联；
  真页面走完 加入→定制→投递→面试 并确认刷新后阶段与 4 条留痕仍在。
