# 角色 B 工作台行为与交接

## 当前主流程：初稿、循环优化、最终预览

- 当前流程为“材料输入 → 确认事实并生成初稿 → 检查与优化 → 简历预览 → 模拟面试”。以下历史记录中“JD 修改撤确认清稿”“JD 为生成前提”“检查后返回预览”的描述由本节替代。
- 用户确认事实后点击“生成初稿并继续”，使用全部已确认经历生成基础稿，无需先填写 JD。无 JD 的生成明确采用初稿路径：保留事实边界、工具自检及数字检查，不执行岗位筛选、范例检索或岗位定制复核，不声称完成岗位定制。失败可重试，不能显示为完成。
- 检查与优化阶段集中展示岗位要求编辑、岗位匹配、简历检查和当前稿编辑。岗位要求可由岗位名称生成、人工补充或粘贴真实 JD；修改 JD 保留事实确认和当前稿，仅使相关诊断、质检和定制依据失效。修改材料、真实事实或取消确认仍清除旧稿并要求重新确认。
- 用户可不限次数重复“检查/匹配 → 选择建议 → 应用 → 更新当前稿 → 再检查”。应用只改写已确认事实；缺口不能自动写成经历。成功提示保留在报告外，失败保留原稿；手工编辑后同样要求复检。报告与当前 JD、事实、Markdown 及版本绑定，迟到响应不能覆盖新输入，请求期间统一锁定导航及工作台恢复。
- 不强制检查次数或质检通过后才能预览。用户点击“查看最终简历”进入预览，可返回优化；预览后再准备面试。面试仍需当前岗位要求、已确认事实和简历；缺少岗位时明确引导回优化填写，不返回事实确认。
- 独立简历检查页的“查看最终简历”也须直接打开工作台的简历预览，沿用当前稿件，不重新生成；“返回修改简历”和普通恢复已有稿仍打开检查与优化。跨页跳转的目标步骤须显式传递，不能只切换到工作台。

2026-10-31 预览跳转修复验收：Edge 使用合成工作台和 Mock API，从独立简历检查页点击“查看最终简历”，旧构建仍显示优化步骤，新构建直接显示预览；返回优化后再次进入预览通过，未调用生成接口，无页面异常。相关 61 项回归测试、生产构建和 TypeScript 检查通过，本地 8000 已重启并引用 `index-MT44YcXW.js`；未部署远端服务器。AGENTS.md 无需更新：本次修复现有导航契约，具体边界在本文件维护。
- 事实确认中的经历查重预览入库入口继续保留。独立旧工具路由兼容保留，但新主流程在同一工作台内完成优化。
- 刷新或显式重新载入工作台时，等待当前账户资料恢复后再挂载工作台步骤。有当前简历稿则进入“检查与优化”，只有事实则进入“确认事实”，空工作台进入“材料输入”。普通编辑不触发自动跳步。

## 目标岗位参考与匹配建议采纳

- 工作台和岗位匹配共用岗位要求编辑器：输入目标岗位名称，由模型生成通用职责及技能要求，先预览，再由用户采用。生成参考不是具体企业 JD 或实时招聘检索，不默认生成学历、年限、证书门槛；已有文本不会被请求结果直接覆盖。
- 用户可以编辑、删除、补充职责，或直接粘贴真实 JD。最终采用的文本存入现有 `jd_text`，修改或采用新文本保留事实确认与当前稿，旧报告失效；生成预览本身不改变工作台。
- 匹配须逐条覆盖职责和任职要求。缺失、重复或非法的模型匹配条目须整份拒绝，已有/部分覆盖的证据须来自已确认材料；模型匹配不代表事实认证。
- 岗位匹配报告与当前 JD、经历和 Markdown 绑定。有依据的条目支持逐条勾选、全选及按选择修改简历；缺少事实的条目仅提示补充真实材料。未确认经历或没有简历时不能应用。
- 应用仅改写、删减或排序已确认事实，不能把岗位要求、诊断建议或输入中的指令转成个人事实。应用成功后旧报告失效，提示重新诊断、质检并人工核对；失败保留原稿，输入变化、卸载或迟到响应不得覆盖新稿。
- 岗位参考生成、诊断和应用期间锁定导航、退出及工作台恢复入口，使用同步请求锁避免重复调用及恢复状态导致请求组件卸载。超过 30 条修订建议明确拒绝，不能静默截断。
- 岗位编辑器接入工作台第 3 步和工作台内的岗位匹配工具，沿用当前两项主导航和海报主题；不增加独立主流程入口。应用成功提示显示在报告外，旧报告清空后仍可查看重新诊断、质检和数字核对提醒。
- JD 解析的职责也必须有可核对的原文片段；任何职责或要求无来源或标为 `inferred` 时，诊断整份报错，不静默过滤或继续优化。

## 主流程导航（2026-10-31）

- 左侧主导航只保留“材料整理与修改简历”和“模拟面试”，个人经历库作为辅助入口。岗位匹配和简历检查不是独立的主流程页面，而是在工作台生成简历后展示的两个优化工具入口，避免用户在多个页面之间来回寻找。
- 工作台生成草稿后，用户可以在同一处分别进入岗位匹配诊断和简历检查；两个工具都围绕当前 Markdown 简历给出修改意见，处理后返回工作台继续编辑。
- 岗位匹配和简历检查均提供返回修改简历的入口；返回后从简历预览/编辑步骤继续。修改事实、JD 或 Markdown 后，旧诊断/质检结果不再代表当前稿件，需重新运行。
- 简历检查未通过时仍允许用户在确认待复核项后进入模拟面试；系统不自动把“未通过”判定为不能面试。

- 生成前提取 JD 原文要求，将要求关联到已确认事实的编号；程序校验原文和引用编号，按有依据的核心要求筛选经历、前置相关行动与成果。无依据要求标为缺口，不补造技能、职责、上线结果或指标。
- 生成后另行执行模型定制复核；只接受正文中真实存在的摘录，并展示要求、事实依据、正文摘录以及未体现/缺口/因篇幅未选入的项目。模型语义判断仍需用户逐句核对，不是事实认证，也不是简单关键词命中率。
- 定制规划或复核失败不静默降级成通用润色。规划、工具生成、复核共享总时间预算（默认 150 秒）；失败允许手动重试，不自动重发整次生成。
- 定制依据只对应当前输入与原始生成稿；编辑、恢复或刷新后没有配套元数据时显示“定制依据待核对”，不复用旧报告、不声称通过。旧接口缺少定制字段仍可查看草稿。

## 个人记忆保存响应边界

- 保存只对应发起请求时的事实与材料名称版本；保存期间仍允许编辑，但事实、确认状态或材料名称变化后，旧请求的成功/失败提示不再用于当前版本。已完成的旧保存不会自动撤销，当前修改需重新保存。
- 修改事实后立即隐藏旧保存提示，即使稍后改回相同内容，也不能恢复旧提示；页面卸载后忽略保存结果。
- 保存使用同步请求锁，重复事件不能发送并行保存；请求结束后解锁，失败允许手动重试，不自动重复写入。

## B 补完迭代

- 不依赖模型也能选择手工填写事实；手工录入不是 AI 解析成功，后续生成仍需模型服务。
- 每段经历须有名称；非教育经历至少填写一项行动或真实成果，才允许确认和生成；不强制量化数字、时间或姓名，不自动编造内容。确认时清理列表中的空白项。

- 四步进度可跳转对应区域；保留原有受控属性、账户自动保存机制和 Markdown 下载。
- 简历预览支持标题、段落、列表、加粗、斜体与行内代码；只渲染安全文本，不执行模型输出的 HTML，也不把未知内容伪装成导出格式。
- 解析/生成请求发出后，如恢复或外部更新改变工作台输入，丢弃迟到响应，不能覆盖新恢复的数据。
- 图片解析已提供独立接口并进入事实确认；真实中文图片识别质量仍需单独验收。Word/PDF、面试评分与历史不属于 B 本轮实现范围。
- 图片模型返回的结构必须包含可用简历内容：姓名、技能、教育，或经历中的名称、角色、时间、行动、成果、技能任一非空字段；姓名可以缺失，但全空对象和只有空字段的经历不会被当作解析成功。
