## 1. 账户、会话与免注册试用

普通账户注册、登录、退出、个人中心和经历库归属隔离遵循本文件。工作台保存及面试记录的后续扩展见本文档第 5 节；原始上传文件二进制留存、多任务历史和长期记忆管理页面不在该扩展范围。

### 用户行为

- 未登录先显示登录页，可切换注册。用户名为 3–32 位英文字母、数字或下划线，大小写不敏感；密码为 8–128 字符，允许中文，不裁剪密码。
- 注册成功直接登录。登录状态有效期为七天，刷新页面后通过服务端确认账户；退出使当前会话立即失效并清空页面中的求职数据。
- 用户名已存在返回 409；错误密码或不存在的账户统一返回 401。未登录访问业务接口返回 401，页面回到登录入口。
- 同一浏览器其他标签页发生登录或退出时，各标签页立即清空临时工作台并重新确认账户；页面恢复焦点时也核对身份，避免旧账户的材料随新账户的 Cookie 继续操作。
- 不提供默认账户、管理员预设或外部身份登录（微信/手机号等）。注册时生成一次性恢复码，凭用户名 + 恢复码可重置密码；恢复码关闭页面后不可再次查看，服务端不保存明文。
- 管理员权限以数据库 `user_roles` 为准，可在「管理后台 → 管理员角色」授予或撤销，服务端校验操作者权限并禁止自行撤销。环境变量 `JOBAGENT_ADMIN_USERNAMES` 仅用于一次性提升已注册账号，不做长期名单。
- 个人中心显示当前用户名和头像，可上传或移除头像、修改密码。头像仅接受 JPEG、PNG、WebP，文件最大 2 MiB，解码校验通过且宽高均不超过 4096 像素后才保存。
- 修改密码必须提供正确的当前密码，新密码沿用注册规则（8–128 字符）。成功后撤销该用户所有旧会话，并为本次请求签发新会话；其他设备的旧会话会失效，同一浏览器的其他标签页共享新 Cookie 并重新核验身份。旧密码错误不改变密码或会话。

### 接口与存储

- `POST /api/auth/register`、`POST /api/auth/login` 接收 `{username,password}`，返回 `{ok:true,user:{id,username}}`。
- `GET /api/auth/me` 返回当前账户；`POST /api/auth/logout` 撤销当前会话。
- `GET /api/auth/profile` 返回 `{ok:true,user:{id,username,avatar_url}}`，无头像时 `avatar_url` 为 `null`；`GET /api/auth/avatar` 仅供已登录用户读取自己的头像。
- `POST /api/auth/change-password` 接收 `{current_password,new_password}`；成功后轮换当前 Cookie 并撤销该账户其他会话。密码错误返回统一的 401，不回显提交值。
- `POST /api/auth/avatar` 使用 multipart 字段 `file` 上传头像；`DELETE /api/auth/avatar` 移除当前账户头像。格式不支持或图像损坏返回 422，文件超限返回 413。
- 使用 HttpOnly、SameSite=Strict、Path=/ 的会话 Cookie；HTTPS 下设置 Secure。本机 HTTP 开发保留可用性。浏览器不保存密码或可读取的会话令牌。
- 所有修改请求要求 `X-Requested-With: XMLHttpRequest`，跨域只允许本机开发页面的明确来源，不使用通配符。会话令牌随机生成，数据库仅保存其摘要与到期时间。
- 使用项目 `data` 目录内的 `accounts.sqlite3` 保存账户、会话、头像、用户经历库、工作台和面试记录；头像以经校验的原始图片字节和 MIME 类型存入当前用户记录，不另写用户可访问路径。密码使用带随机盐的 PBKDF2-HMAC-SHA256，不存明文；数据库不入 Git。
- API key 分两类：平台默认端点写在服务端私有配置（本机 `backend/.env`，服务器 `JOBAGENT_ENV_FILE`）且不入 Git；用户个人模型的 Key 以 AES-256-GCM 密文存入账户数据库，密钥用 `JOBAGENT_MODEL_ENCRYPTION_KEY` 单独保管。两者都不是用户业务资料，也不随响应返回。
- 所有现有业务路由要求登录；经历库列表、加载、保存和删除都按服务端当前用户 ID 限定查询，未知及其他用户的 ID 统一 404，不接受客户端指定归属。
- 旧 `data/profiles` 共享文件不迁移、不删除，也不对新账户暴露。新账户从空经历库开始。
- 健康检查、前端静态文件和登录注册入口可匿名访问。材料解析和生成接口仍按请求处理，前端通过独立工作台接口保存状态，见本文档第 5 节。

### 验收

使用临时数据库验证两个账户的注册、重复注册、登录失败、会话恢复、退出及过期；验证匿名业务访问被拒绝，A 保存的经历在 B 的列表中不可见，B 无法读取或删除，A 仍可读取。验证修改密码需要正确旧密码、成功后仅新当前会话有效；验证头像格式、尺寸、损坏文件、删除及账户间隔离。外部模型使用 Mock，不调用真实资料。

前端验证注册、退出、重新登录、刷新恢复账户、错误可见和账户切换清空工作台；桌面和手机页面无横向溢出。该轮只在本机运行，不包含部署或公开服务发布。

### 个人文本模型

登录后可在个人设置填写 Base URL、模型 ID 和 API Key，并用固定测试提示验证后启用。配置按账户持久化，重新登录、换设备或重启服务后仍可使用。文本模型使用用户选择的服务，失败时明确返回错误；图片识别使用单独配置的图片模型。实际使用自定义模型时，求职材料会发送给所选服务商。

### 管理员用户统计

管理员可在个人设置查看注册总数、北京时间本周新增，以及近五分钟有页面心跳的已登录账户数。每个账户只计一次，退出或失效的会话不计入在线数。在线数据为进程内近似值，重启后由页面心跳重新建立。统计只返回汇总，不暴露其他账户的资料。

#### 模型列表和自定义服务商

服务商预设填入 Base URL。用户可从 `GET {base_url}/models` 获取模型 ID，也可手动填写后测试。自定义 OpenAI 兼容服务必须由管理员在 `JOBAGENT_CUSTOM_MODEL_BASE_URLS` 中配置完整 HTTPS Base URL，逗号分隔，仅添加可信公网端点，配置后重启。列表查询不会启用或改写当前配置。

自定义选项也接受内置服务商的官方 Base URL。DeepSeek 官方地址带 /v1 时按同一端点处理，无需管理员重复登记。

模型配置使用独立操作按钮，API Key 输入默认遮挡。获取列表失败时区分网络错误、服务商拒绝访问和列表接口不可用，并保留手动填写模型 ID 的入口。

个人设置只展示自定义连接，填写 Base URL、API Key 与模型 ID。旧版服务商配置仍可读取。可独立移除文本或图片模型配置。

启用成功后，API Key 以 AES-256-GCM 密文保存在服务端数据库。界面显示已保存，可留空复用同一 Base URL 的 Key。更换供应商或 Base URL 需填写对应的 Key。

已保存的 API Key 默认遮挡。本人可点击眼睛图标短暂显示，查看响应禁止缓存。

旧浏览器配置会在登录后尝试迁移，服务端已有配置时采用服务端版本。只有服务端已有配置或迁移保存成功后才删除旧条目。新配置不会写入浏览器存储。网站管理员账号只能管理自己的模型配置。数据库只读人员只能看到密文和配置元数据。后端调用时解密，能控制服务端进程或同时持有数据库和加密密钥的运营者仍能取得密钥。

### 免注册试用

试用使用独立的两小时临时会话，进入正式工作台，可填写材料、确认事实、生成简历、按岗位检查、导出和模拟面试。试用也可使用临时经历库。页面刷新可恢复试用进度；退出试用会清除临时工作区，过期会话不可继续访问。试用数据不会归入注册账户。试用可在工作台右上角临时配置文本模型，验证成功后文本任务使用该配置。访客密钥仅保存在服务进程内存，退出、到期或重启后失效；图片解析使用独立的临时图片模型。

文本与图片解析模型分别配置和验证。业务接口只用当前用户对应的模型，缺少配置时提示先启用，不回退到平台模型。图片模型启用时用程序生成的样例图片验证。

工作台或面试请求缺少模型配置时，弹窗提示对应模型，并提供进入模型设置的按钮。关闭弹窗可留在当前页面。

访客首次进入工作台且没有启用文本模型时，显示一次配置指引。同一浏览器标签页刷新后不重复提示，已启用模型的访客和登录用户不主动弹窗。具体操作缺少模型时仍可提示。

## 2. 个人模型与 API Key

个人模型分文本与图片两类，各自独立配置、独立校验，业务请求只使用当前账户自己启用的模型
（缺配置返回 428 并提示去配置，不用平台 key 兜底）。详细规则见上面「账户、会话与免注册试用」
里的「个人文本模型」「模型列表和自定义服务商」「免注册试用」小节；补充约定：

- API Key 以带版本的 AES-256-GCM 密文入库，密钥来自 `JOBAGENT_MODEL_ENCRYPTION_KEY`，
  绑定用户与端点；常规响应与日志不含明文，仅本人经显式请求可查看且响应 `no-store`。
- 更换供应商或 Base URL 必须填写新 Key；同一端点留空可复用已保存的 Key。
- 图片模型启用时会用程序生成的样图做一次真实调用；若上游提示不支持图片输入，
  前端提示"这个模型不接受图片输入，请换成支持读图的模型"（例如 DeepSeek `deepseek-flash`，
  而 `deepseek-v4-pro` 只读文本）。

## 3. 管理员与权限

站点分**用户端（`/`）**与**管理端（`/admin`）**两个入口，普通人只能进用户端。

- 管理员角色以数据库 `user_roles` 为准；公开注册的账号一律是普通用户，
  **不存在"谁先注册谁是管理员"的自助入口**。
- 创建管理者只有一条路：运维执行 `backend/manage.py admin create 用户名`
  （或 `admin grant 已注册用户名`）。管理端 `/admin` 只负责登录并校验角色：
  未登录显示管理员登录页，普通账号显示"仅管理员可访问"。
- 授予和撤销角色须由服务端验证操作者权限，禁止撤销自己的管理员角色，
  CLI 也不允许撤销最后一个管理员。
- 后台统计只返回汇总数据；站内反馈仅对提交者和管理员可见。

## 4. 个人经历库

上传/手工材料先解析和核对，再预览查重结果；未确认事实不能入库。每个项目或任职独立成卡，教育仅保留学校、学历/专业及起止时间，行动、成果、技能为空。旧快照保留为历史材料，确认整理后标记已整理，不自动删除原文。

查重按账户隔离。规范化后的相同事实跳过；相似名称/内容仅提示候选，不自动合并。新增项目、归入已有项目、跳过均可选择。合并只追加用户选中的来源事实；名称、角色、时间和数字不同需明确选择保留旧值或采用新值，不自动重写；不调用模型润色或推断事实。来源保留输入原文和解析事实。

服务端在事务中重新查重并检查库版本；重复提交与并发请求不得制造重复卡片。回收站、版本恢复均作为新版本记录，保留来源与旧版本。卡片选择后组装为工作台材料，撤销事实确认、清空旧稿并保留 JD；生成稿不会回写事实库。未知教育描述从旧材料中人工整理，禁止自动猜测学校/日期。

历史数据迁移先预览，逐项确认，原快照可继续查阅；库版本变化需重新预览。账户切换/卸载忽略迟到响应。原始材料、数据和密钥不得入库到 Git。

卡片默认收起，仅显示标题和选择控件；点击标题展开完整事实及操作。标题需与正文区分，回收站和来源历史操作必须有可见边框及键盘焦点样式，展开不改变卡片选择。

经历卡片按独立列排列，各列内容自然向下衔接，单张卡片展开不应撑高其他列的行间距；窄屏恢复单列及原始卡片顺序。

导入预览不再显示“导入前查重”标题，保留可访问区域名；查重说明使用蓝色小字提示，关闭预览用突出的蓝色按钮。载入确认说明使用至少 16px 字号，确认与取消按钮有边框并与说明分区，取消不替换工作台。

### 分类切换

- 顶部有分类页签：全部 / 教育经历 / 项目经历 / 工作 实习 / 其他经历，并显示各类卡片张数。
- 只渲染当前分类的卡片；空分类页签禁用，不显示空区块。
- 卡片总数 > 6 时默认聚焦**卡片最多的那一类**，否则默认「全部」——避免一进来就以为卡片丢了。
- 分类只影响展示与筛选，不改变卡片身份、选择状态或已保存事实；载入工作台仍按所选卡片集合。

## 5. 工作台自动保存与历史

### 本次交付边界

每个账户保留一份当前求职工作台：原始文本、材料名称、JD、结构化经历、确认状态、JD 关键词、Markdown 简历和当前页面。刷新或重新登录后恢复。上传文件仅保存解析后的文字和文件名，不保存原始二进制文件；未完成的模型请求不恢复执行。多任务列表、简历版本对比、面试生成与评分不在本次范围。

保存中、保存失败、恢复失败必须可见。恢复成功前禁止编辑和写入；失败可重试。编辑后约 600 毫秒自动保存，写入串行执行；退出登录先完成待保存内容，失败时保留页面供重试。未保存时关闭页面给浏览器离开提示。跨标签页版本冲突返回 409，不自动覆盖；用户可以明确选择加载服务器版本（会放弃本页未保存编辑）。

### 账户与并发契约

所有接口要求账户 Cookie，写请求要求 `X-Requested-With: XMLHttpRequest`。新增 POST 保存请求必须携带 `expected_user_id`，服务端与当前登录账户比较，不一致返回 409，避免切换账户期间的旧页面写入新账户。DELETE 按记录 ID 和服务端当前账户共同限定，不需要请求体。不得接受客户端指定数据归属。

`GET /api/workspace` 返回 `{ok:true, revision:0, state:null, saved_at:null}` 或已有状态。`POST /api/workspace` 接收 `{expected_user_id, revision, state}`，revision 为最近读取或写入成功的版本；只有版本一致才能写入，成功后返回 `{ok:true, revision, saved_at}`。首次保存版本为 0。状态结构固定如下：

```typescript
type WorkspaceState = {
  source_text: string; source_name: string; jd_text: string;
  profile: ResumeProfile | null; jd_keywords: string[]; markdown: string;
  page: 'workbench' | 'diagnose' | 'quality' | 'interview' | 'memory';
}
```

`profile` 使用现有经历库格式。无保存记录不是错误；网络或服务错误不得当作空记录。非法结构返回 422，工作台状态序列化 JSON 的 UTF-8 大小超过 2 MiB 返回 413。恢复保存中的确认状态不代替用户核对；编辑经历或 JD 继续按已有规则撤销确认和清空旧稿。

### 面试记录

`POST /api/interview-records` 接收 `{expected_user_id, title, jd_text, questions, answers, question_scores, overall_feedback}`。questions 为对象数组，answers 为字符串数组，question_scores 为对象数组，overall_feedback 为对象；允许保存尚未评分的记录，字段默认空数组或空对象。这里只存储，不产生评分、不证明评分内容正确。每次 POST 创建独立记录，调用方应在一轮结束后提交一次，避免重复点击。

成功返回 `{ok:true, id, saved_at}`。`GET /api/interview-records` 返回 `{ok:true, records:[{id,title,saved_at}]}`，按时间倒序。`GET /api/interview-records/{id}` 返回 `{ok:true, record:{id,title,saved_at,jd_text,questions,answers,question_scores,overall_feedback}}`。`DELETE /api/interview-records/{id}` 删除成功返回 `{ok:true}`。未知或其他账户记录统一 404。

前端将记录 ID 放入 URL 路径时必须使用 `encodeURIComponent`，确保 ID 始终作为单一路径段传输。保存请求中的 `expected_user_id` 必须来自本轮开始时的账户身份。

单条面试记录序列化 JSON 的 UTF-8 大小限制为 1 MiB，标题最多 200 字符；超出记录大小返回 413，结构或标题不合法返回 422。记录存储在本机已有 SQLite 数据库，不依赖外部模型。暂不保留原始录音，不提供跨账户访问。

### 验收

## 6. 模型错误与接口约定

共享模型客户端统一处理简历与 JD 接口的模型错误。成功返回字段保持现状；错误响应采用 HTTP 状态码和 `{detail: 中文提示}`，前端继续使用 `apiErrorMessage`。

### 状态约定

| 场景 | 状态 | 用户可见行为 |
| --- | --- | --- |
| 应用账户失效 | 401 | 提示重新登录，由现有账户机制处理 |
| 简历或 JD 输入为空、上传无法提取文字 | 422 | 提示检查输入，不调用模型 |
| 未启用所需的文本或图片模型 | 428 | 弹窗提示并提供前往模型设置的入口 |
| 上游模型限流，重试后仍失败 | 429 | 提示稍后重试，不退出应用账户 |
| 模型配置、上游鉴权、连接或服务不可用 | 503 | 提示检查模型服务配置或状态，不作为应用登录失效 |
| 上游请求超时或调用预算耗尽 | 504 | 明确失败，不交付未完成稿 |
| 模型空响应、响应结构错误、JSON 修正后仍无效 | 502 | 明确产物无效，不把空结果作为成功 |

用户业务请求只使用当前用户对应的模型配置。错误分类使用异常类型和 HTTP 状态，不从上游响应正文猜测；原始异常通过异常链保留供诊断，接口不返回上游正文、请求地址、凭据或材料。上游鉴权失败不应在同一 provider 重试，也不切换到平台模型。

工具循环中的模型调用失败须保留真实分类，不吞掉为 `deadline_hit`。正常耗尽工具循环或流程预算仍保留原有未完成标记，由简历接口拒绝交付。工具执行机制、生成提示词和质量规则保持原行为。

JD 定制复核的正文引用使用程序切分的片段目录：模型选择 `excerpt_id`，程序按编号回填原始 Markdown 片段，不要求模型复制或拼接正文。要求体现项与疑似夸大断言均使用同一目录；空编号仅表示该要求尚未体现。未知编号、缺项、重复要求或无效事实关联仍明确拒绝整份报告，不做模糊匹配或静默跳过。正文引用仍须通过本项已选事实编号、关系解释及共同片段检查；片段编号只保证引用原文，不能认证事实或语义判断。

### 接口错误处理

简历解析、生成和岗位诊断接口沿用统一模型错误处理。其他未知业务异常沿用原错误机制，避免将程序错误误判为模型限流。

匹配诊断的语义匹配阶段若发生模型错误，同样返回失败；不把缺少该阶段结果的关键词覆盖报告作为完整诊断交付。前端公共请求层保留原 Axios 错误对象及响应，并把 `message` 设为统一中文提示，使既有页面的错误显示也能读取服务端提示。

模拟面试接口沿用统一错误分类。上游 401 不应作为应用账户 401 返回，题目和评分结果仍须通过业务字段校验。

使用 Mock 覆盖上游 401、429、503、超时、连接失败、空响应、非法 JSON、工具循环中断和正常结果；不使用真实材料，也不需要真实模型调用。

## 7. 面经与内推（社群）

面向求职者的匿名内容：面经、内推、JD 评价。目标是让有用的真实信息流动起来，同时让投稿的人不因为说真话被认出、被追责。

### 谁能做什么

| 角色 | 能力 |
| --- | --- |
| 试用账号 | 可以浏览已公开内容；**不能**投稿、举报、撤回 |
| 正式账号 | 浏览、投稿、看自己的投稿状态与退回理由、撤回自己的投稿、点「有帮助」、举报 |
| 管理员 | 上面的全部，加上审核队列、通过/退回、删除违规内容 |

管理员身份以数据库 `user_roles` 为准；部署时没有管理员时用 `backend/manage.py admin grant <用户名>` 开通。

### 状态机

```
投稿 → pending（待审核）
        ├─ 管理员通过 → public（公开，带 published_at）
        └─ 管理员退回 → rejected（必须写理由，作者可见）
rejected ──作者编辑或「重新提交」──→ pending（旧退回原因清空，重新排队）
public ──作者编辑──→ pending（内容变了必须重审，先从列表撤下）
public ──管理员下架──→ rejected（作者看到下架原因，可编辑后重新提交）
public 累计 3 条举报 → 自动退回 pending（先从公开列表撤下，等管理员处理）
作者撤回 → 记录删除（管理员也可删除违规内容）
```

**被退回或下架后怎么再次发布**：作者在「我的投稿」点「编辑」把内容装回表单（或内容没改直接
「重新提交」），保存后回到 `pending`，管理员通过即重新公开。已发布内容一旦被作者编辑，也会
自动回到 `pending` 并从列表撤下——不能沿用上一次的审核结论。

### 版本语义（编辑 = 新一版）

同一张卡片"改内容再发"不是原来那篇，所以：

| 数据 | 编辑后 | 原因 |
| --- | --- | --- |
| `revision` | +1 | 记录这是第几版，详情页显示「第 N 版」 |
| 有帮助票 | **作废**（`card_votes` 清空，`helpful_count` 归零） | 票是对上一版内容的认可，不能顺延给新内容 |
| 评论 | **保留**，按 `revision` 归属；列表里折叠成「上一版内容下的评论（N）」，虚线样式，不能再举报 | 保留讨论价值，但不能让读者误以为这些评论在说新内容 |
| 举报 | 待处理的旧举报按"内容已更新"结案（`resolved`），`report_count` 归零 | 旧举报针对旧内容，不该拖着新内容 |
| 状态 | `pending` | 新内容必须重新审核 |

「重新提交」（内容没改）不算新版本：`revision` 不变，帮助票与评论继续有效。

#### 历史版本

- 每次投稿/改内容都会往 `card_revisions` 写一份快照（`card_id + revision` 唯一），
  同一版本重复写只保留第一次。
- `GET /api/community/cards/{id}/revisions`：版本列表（不含正文）；
  `GET /api/community/cards/{id}/revisions/{n}`：某一版全文。
- **只有作者和管理员能看历史**（历史内容可能因合规被撤下，不能让任何人翻旧版）。
  管理员处理举报时需要能对照旧版，所以一并放开。
- 前端「我的投稿 → 历史版本」：版本切换按钮，选中某版会把它的**上一版**拉出来做行级
  对比（绿色新增/红色删除，附"新增 N 行、删除 M 行"）；第 1 版提示没有上一版可对比。
- 本功能上线前创建的老卡片没有快照，第一次查历史时会自动把当前内容补一份，至少能看到现状。

- **只有 `public` 出现在公开列表**，过滤写在 SQL 条件里（`engine/community/cards.py`），不依赖前端隐藏。
- 未公开内容只有作者和管理员能读到详情；其他人一律 404。

### 匿名与隐私

- 对外只返回马甲名（如「安静的青柠 42」），接口不返回 `user_id` 或 `anon_id`。
- 同一账号多次投稿复用同一个马甲：读者能把同一个人的多条内容串起来，但串不到账号。
- 账号与马甲的对应关系只存在服务端 `anon_identities`，用于管理员处理举报；不提供任何对外查询。
- 入库前脱敏（`engine/community/redact.py`）：手机号、邮箱、证件号、QQ、微信替换成占位符。
  公司名、岗位名、年份、薪资区间属于内容价值，不脱敏。
- 脱敏发生在**写库前**，审核通过时不再二次处理，避免同一个卡片因为复核顺序不同而出现两种文本。

### 内容来源

- 手写正文，或用「引用收件箱资料」下拉选一条**自己录入**的资料（`GET /api/jobs?mine=true`）。
  下拉只列本人的资料：公共岗位池是采集来的公告，拿来当投稿正文来源全是无关转载。
- 用户看不到也不需要知道内部 ID，所以不给裸 ID 输入框。选中资料后表单会带入标题/公司/岗位，
  让用户看清自己在引用什么。
- 选中的资料不可用（被删除或不属于当前账号）时返回 **422 表单错误**并提示"重新选择，或留空直接写正文"，
  既不是 404（这不是页面不存在），也不会静默忽略——静默忽略会让用户以为自己引用了资料。
- 从资料带入时仍走同一套脱敏与审核，不因为"自己的资料"跳过。

### 互动

- 有帮助：一人一卡一票，**再点一次可以撤回**（`card_votes` 主键去重，计数随之减 1）。
  卡片详情会带 `viewer_helpful`，刷新后按钮仍显示"已标记"。
- 举报（内容）：一人一卡一次，必须写原因。举报会**进管理员「举报」页签**（按卡片聚合，
  带每条原因、时间、当前状态），不是只加一个计数。管理员可以选择：
  - 「标记已处理」：人工核对为正常，内容保留，举报记录置为已处理（保留便于复盘）；
  - 「删除内容」：直接删除（举报与评论随级联消失）。
  累计 3 条举报的内容会先自动从列表撤下回到待审，等管理员处理。
- 已发布内容的管理：管理员可在「已发布管理」里**下架**（`status = 'rejected'`，作者在
  「我的投稿」看到下架原因）或直接删除；作者自己也能随时撤回已发布内容。
- 作者修改：`PUT /api/community/cards/{id}` 保存修改并重新进入待审（同时写一份版本快照；`published_at`、
  审核人、旧退回原因一并清空，`revision` +1 并按上面的版本语义重置互动数据）；
  `POST /api/community/cards/{id}/resubmit` 用于"内容没改、直接重新提交"，保留版本与互动。
  两者都只能操作自己的投稿，且同样走脱敏与长度校验。
- 评论：评论**即时公开**（不再走一遍审核），入库前同样脱敏；只能评论已公开的卡片，
  试用账号不能评论。被举报累计 2 条先撤下进「举报 → 被举报的评论」，管理员可恢复或删除；
  同一个人对同一条评论只能举报一次。作者可删除自己的评论。

### 字段展示

卡片详情用带标签的字段格展示：类型 / 公司 / 岗位 / 轮次 各占一格，列表里用类型徽标 +
「公司 · 岗位 · 轮次」；不再把四种信息混成一行无法区分的标签。
