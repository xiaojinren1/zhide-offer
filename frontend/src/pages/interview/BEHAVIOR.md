# 个性化题库与连续文字面试

## 用户行为

- 准备页始终提供「生成个性化题库」与「直接进入全真模拟」两个入口。均使用工作台最新生成的简历、对应已确认经历和当前 JD；不足时逐项提示。无需生成题库即可直接模拟，题库也无需看完才能模拟。
- 两个入口并排时按钮靠卡片底部对齐，说明换行不影响按钮位置；窄屏保持单列。直接模拟卡片省略题量补充说明，题库数量规则保持不变。
- 题库由模型根据独立经历、项目深度与岗位能力生成 10–30 道有效题，不按文字长度机械增加或重复凑数，覆盖四类。最新简历用于选择重点；事实仍仅来源于已确认资料。历史题库保留实际数量，不受新生成数量限制。
- 直接开始只用一次模型调用生成轻量考察主题与自我介绍首问，不生成完整题库或示范。10 题下限仅适用于准备题库，面试无需问满 10 题。
- 示范回答默认折叠。示范中的事实由服务端从已确认资料摘录组装，模型只选择事实编号和提供结构建议，不自由编写候选人经历。
- 开始面试后冻结材料，隐藏题库、示范回答和评分。每次只展示一个待回答问题，结合完整对话动态追问；可以跳过、回答不知道、继续或主动结束。
- 15 分钟为参考，等待接口响应不计时；到时提醒但不强制结束。切换页面或刷新不提供进行中面试续接。
- 回答最多 12000 字；空白、超长、422 对象错误、非 JSON、模型失败均显示中文提示，保留草稿重试，不白屏、不重复追加回答。
- 结束后统一展示 HR 和岗位面试官视角、五个等权维度、引用原回答的亮点和最多三项改进、回答优化及对应题库主题。不显示逐题数字分数。
- 评分是模型按明确标准给出的练习评价，不使用关键词/字数计分，不推断录用概率或认证真实性。未充分考察的维度无分数；不足三次非跳过回答或任何维度证据不足时不显示完整总分。
- 已结束记录复用现有账户隔离的 interview_records 表及读取 API，存入材料快照、完整对话和报告。报告保存失败保留结果并可单独重试，成功后不重复创建记录。旧格式历史可只读查看。

## 接口与协作

- 新增 `POST /api/interview/bank`、`/start`、`/turn`、`/report`，所有写请求携带 expected_user_id 和安全请求头。题库/面试 ID、版本、重试请求 ID 由服务端校验；材料与对话以服务端状态为准。
- /bank 接收 resume_profile、resume_markdown、jd_text、request_id，返回 bank 对象，其 id 是后续使用的 bank_id，含冻结快照、事实来源和 10–30 题。全部题目的 source_ids 合集须同时包含简历和 JD 来源，示范回答只引用已确认简历事实；来源校验失败不保存题库，可用原请求体手动重试，成功后重复请求复用原题库。
- /start 接收 bank_id 或完整的 resume_profile、resume_markdown、jd_text，两种输入互斥；返回会话、入口模式和材料快照，不返回示范或辅导。失败不落地半完成会话；相同请求重试不重复创建。/turn 的 bank_id 开始方式仅为旧客户端兼容保留；后续接收 session_id、version、answer、skip、elapsed_seconds、request_id。失败不提交当前回答。
- /report 接收 session_id、version、elapsed_seconds、final_answer、request_id，先冻结结束状态及最后一条草稿，生成结构化报告，再写入现有记录表；必须用相同请求体重试，复用已有报告和记录 ID。所有 evidence（包括空分维度的证据）及 answer_excerpt 必须是同一 turn_id 下实际非跳过回答的逐字连续片段，保留空格和标点，不得拼接或改写；来源和主题编号不能充当回答编号。引用校验失败不生成报告或历史，结束状态和末答仍保留，原结束请求重试不重复追加末答。保存失败时不重新调用评价模型；保存成功后删除的记录不能通过旧请求重新创建。
- 临时题库和会话使用同一账户数据库内的 interview_artifacts 表，超过七天清理，不作为刷新续接功能。每轮最多 100 次对话，到达上限仍可结束复盘。已完成历史不随临时状态过期清理。
- 新完成历史使用 schema_version: 3，含 mode、snapshot、context（岗位、事实来源、考察主题及简历/JD）、可空 bank、transcript、report、elapsed_seconds。直接面试不产生题库跳转，报告显示练习主题；兼容 schema_version: 2 和旧格式，无需新表。
- 历史题库只用于回看与定位练习主题；下一轮可以基于当前材料直接开始，也可以重新生成题库。报告未保存成功时禁止替换本轮内容。
- 旧 /api/interview 与 /score 保留兼容，但新页面不调用旧规则评分。
- C 使用面试专用请求封装，不改 A 的 App.tsx/api.ts。App 顶部旧提示与导航改名、共享请求方法迁移的具体建议见 INTERVIEW_INTEGRATION.md。

## 验收

请求编号须兼容普通 HTTP 页面：使用浏览器 `crypto.getRandomValues` 生成 UUID v4，不依赖仅安全上下文提供的 `crypto.randomUUID`。同一失败请求重试保留编号和请求体；请求失败后解除忙碌状态，允许再次操作。

使用两份不同虚构材料，分别验证题库差异、事实追溯、动态追问、隐藏示范、全程无逐题分数、15 分钟提醒、提前结束、保存与历史。Mock 与真实模型验证分别记录；不得将未完成真实联调标为通过。

具体结果与复现命令见 [ACCEPTANCE.md](ACCEPTANCE.md)。
